# 작업 진행 기록

## 2026-09-23 — 첫 구현

- JARVIS 작업 공간을 준비하고 제품 요구사항과 아키텍처를 구체화했다.
- React 19, TypeScript, Vite와 Astryx neutral 테마를 구성했다.
- 아이보리·민트 글래스모피즘 UI와 반응형 화면, 텍스트 항목 편집, 가중치 기반 뽑기, 당첨 제외, 기록과 로컬 저장을 구현했다.
- Vercel 정적 배포 설정과 한국어 실행·배포 안내를 작성했다.
- 기존 파일 존재 검사 전용 `scripts/verify.ps1`을 실제 lint·타입 검사·단위 테스트·프로덕션 빌드 검증으로 교체했다. 각 명령의 종료 코드를 검사하며 `-WithBrowser`로 브라우저 검증을 추가할 수 있다.

## 남은 작업과 경계

- 위 `outputs/browser/` 자료는 로컬 검증 증거이며 Git 저장소에는 포함하지 않는다. `npm run test:e2e`로 브라우저 테스트와 HTML 보고서·스크린샷을 새로 생성할 수 있다. 수동 검토 요약인 `validation.md`와 별도 프로덕션 확인 결과인 `production-smoke.json`은 해당 명령이 자동 생성하지 않는다.

- Vercel 공개 배포가 완료되어 https://bbkk-ivory.vercel.app/ 에서 서비스 중이다. 러닝 약속 변경의 재배포 상태는 아래 기록을 따른다.
- 실제 iOS Safari 기기 검증이 남아 있다. 이번 브라우저 검증은 Chromium과 모바일 크기 시뮬레이션 범위다.
- 초기 버전은 브라우저 전용 저장이었다. 공유 목록 전환 범위와 최신 상태는 아래 작업 기록을 따른다.

## 2026-09-23 — 러닝 약속으로 조정

- 사용 목적을 이틀 연속 러닝을 쉬었을 때의 벌칙 뽑기로 조정한다. 기존 디자인과 기능은 유지하고 화면 문구를 줄인다.
- 페이지 제목과 메타데이터를 `bbob — 러닝 약속`, `이틀 연속 쉬면, 벌칙 하나.`로 변경했다.
- 기본 벌칙은 청소 20분, 설거지 전담, 친구에게 커피 사기, 배달 대신 직접 요리, 미뤄둔 일 30분이며 각각 20%다.
- 사용자 항목과 기록을 보존한다. 정확히 일치하는 미사용 점심 기본 샘플만 새 벌칙 기본값으로 전환한다.
- 러닝 기록, 달력과 연속 일수 자동 판정 기능은 추가하지 않는다.
- 이번 변경의 최종 로컬 검증은 Vitest 32개, Playwright 8개, `npm run build`, `npm run lint` 모두 통과했다.
- 공개 주소는 https://bbkk-ivory.vercel.app/ 이다. 배포 상태는 GitHub의 Vercel 검사에서 확인하며, 이 커밋의 배포 후 공개 페이지 검증 결과는 로컬 review 기록과 Obsidian 작업 요약에 남긴다.

## 2026-09-23 — 네 등급과 알 공개

- 기존 미니멀 글래스모피즘 화면에 상·중·하·극하 벌칙 탭과 알 공개 단계를 추가하는 요구사항을 반영했다.
- 등급 확률은 상 60%, 중 35%, 하 4.9%, 극하 0.1%로 고정한다. 각각 흰색·파란색·금색·빛나는 금색 알로 표현하며, 알을 누르면 해당 등급에서 균등 선택한 벌칙을 공개한다.
- 어느 등급이 비거나 당첨 제외로 소진되면 확률을 재분배하지 않고 뽑기를 막는다. 항목 채우기 또는 전체 포함으로 복구한다.
- 기존 기본 벌칙 5개는 상·상·중·하·극하로 배치한다. 사용자 항목과 기록은 보존하고 등급 없는 사용자 항목은 상으로 이관한다.
- 공개 대기 중인 알은 새로고침 후 복원하고, 한 추첨의 기록은 공개 시 한 번만 남기도록 설계한다.
- README·PRD·아키텍처를 새 동작에 맞게 갱신했다. 이번 코드에서 Vitest 47개, Playwright 14개, 전체 ESLint, TypeScript 포함 프로덕션 빌드가 통과했다.
- 확률 구간 10,000개를 전수 확인하여 상 6,000·중 3,500·하 490·극하 10개를 검증했다. 브라우저에서는 알 생성과 공개 분리, 네 색상, 공개 전 기록 없음, 새로고침 시 알 복원, 등급 이동, 빈 등급·소진 차단, 기존 데이터 전환과 60자 모바일 결과를 확인했다.
- 데스크톱과 320·390·768·1440px 검증에서 가로 넘침과 페이지 오류가 없었다. 근거는 `tests/e2e/studio.spec.ts`, `src/lib/draw.test.ts`, 로컬 `outputs/browser/`의 화면 캡처와 검증 기록이다.
- 공개 배포의 최신 상태는 GitHub의 Vercel 검사에서 확인한다. 배포 후 공개 페이지 검사 결과는 로컬 review 기록과 Obsidian 작업 요약에 남긴다. 실제 Safari 기기 검증은 포함하지 않았다.

## 2026-09-23 — 공유 목록 전환 (로컬 검증)

- 하나의 벌칙 목록을 Supabase에 공유하고 기록·설정·제외·알 후보는 브라우저별로 분리하는 명세를 확정했다.
- 자동 저장, revision CAS, 3방향 병합, 충돌 선택, 네트워크 실패 복구, 이전 기기 목록의 명시적 가져오기를 구현했다.
- 초기화 확인에 `모두의 목록이 바뀝니다.`를 표시한다. 기존 개인 목록을 서버로 자동 덮어쓰지 않는다.
- 기존 14개 브라우저 검증은 페이지별 모의 RPC로 격리했고, 두 컨텍스트의 공유·CAS 병합·충돌 선택·오프라인 복구·개인 상태 분리와 기존 기기 목록의 명시적 가져오기 6개를 추가했다.
- 최종 전체 브라우저 20개가 한 번의 실행에서 모두 통과했다(1.6분). 리뷰에서 발견한 초기화 취소의 원격 변경 보존과 미저장 떠나기 경고를 보완한 뒤 해당 회귀 테스트 2개도 통과했다(20.8초). 전체 모음은 현재 22개이며 모의 RPC만 사용하여 공개 DB는 변경하지 않았다.
- 실제 공개 DB 확인 스크립트는 고유 테스트 항목 1개만 추가·수정한 뒤 그 ID만 제거하고 새로고침 후 제거를 확인하도록 준비했다. 사용자 목록 전체 복원이나 초기화는 하지 않는다.
- 최종 코드의 Vitest 75개, 전체 ESLint(경고 없음), TypeScript 포함 Vite 빌드가 통과했다. 빌드 자산은 `index-nx5O2zqd.js`와 `index-C9aC7MlN.css`다.
- 초기화 되돌리기는 역방향 변경만 최신 목록에 병합하여 다른 사용자의 이후 추가·수정을 유지한다. 충돌·개수 초과 시 차단한다. 실제 미저장 수정에만 브라우저 떠나기 경고를 표시하며 저장 완료나 수정 없는 오프라인 조회에는 경고하지 않는다.
- 공유 버전의 공개 배포·실제 DB 동기화 검증 결과는 실행 후 로컬 review 기록과 Obsidian 프로젝트 요약에 남긴다. 로컬 테스트 통과만으로 공개 배포를 완료로 간주하지 않는다.
