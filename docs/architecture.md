# bbob 아키텍처

## 실행 구조

React 19와 TypeScript로 만든 Vite 단일 페이지 앱이다. Vercel은 `npm ci` 후 `npm run build`를 실행하고 `dist`를 배포한다. 공유 항목은 서울 리전의 Supabase Postgres에 저장하며 브라우저는 제한된 공개 RPC를 호출한다. 브라우저 코드에는 API 주소와 publishable key만 포함한다.

이틀 연속 러닝을 쉬었을 때 사용자가 직접 벌칙을 뽑는다. 운동 추적이나 날짜 계산 상태는 추가하지 않는다.

- `src/main.tsx`: React 진입점, Astryx의 사전 빌드된 코어·중립 테마 CSS와 앱 CSS 로드.
- `src/App.tsx`: 등급 탭과 항목 편집, 알 뽑기·공개, 기록 및 저장 UI.
- `src/lib/`: 고정 등급 확률과 균등 선택, 대기 알 상태, 저장 데이터 검증·이관 등 UI와 분리된 로직.
- `src/config/shared.ts`: 공유 API 주소와 공개 클라이언트 설정. 서비스 역할 키·DB 비밀번호는 포함하지 않는다.
- `src/lib/sharedBoard.ts`: RPC 검증·CAS 저장·3방향 병합과 동기화 상태 관리.
- `src/hooks/useSharedBoard.ts`: React 연결과 보이는 탭의 3초 조회, 포커스·온라인 전환 시 갱신.
- `src/index.css`: 아이보리·민트 글래스모피즘, 반응형 배치와 모션 감소 지원.
- `public/`: 정적 아이콘. `index.html`: 한국어 메타데이터.

## 디자인 시스템

Astryx 코어와 neutral 테마를 사용한다. 코어와 테마의 배포 CSS를 가져오므로 앱을 위한 별도 StyleX 컴파일 파이프라인은 두지 않는다. 프로젝트의 유리 패널과 뽑기 장면은 앱 CSS로 표현한다.

## 데이터 흐름

등급 탭의 텍스트 입력 → 550ms 자동 저장 → revision을 검사하는 공유 RPC → 저장·연결 완료 확인 → 모든 등급의 선택 가능 여부 확인 → Web Crypto 난수로 고정 확률의 등급 선택 → 해당 등급의 후보 스냅샷과 알을 개인 브라우저에 저장 → 사용자 공개 동작 → 후보에서 균등 선택한 벌칙과 개인 기록 표시.

## 공유 저장과 동시 편집

공유 레코드는 `items`, `revision`, `updated_at`을 갖는다. `bbob_get_board` RPC가 현재 레코드를 반환한다. `bbob_save_board`는 `p_expected_revision`, `p_items`, `p_request_id`를 받고 `{status: 'ok' | 'conflict', board}`를 반환한다. 서버는 예상 revision과 현재 revision이 같을 때만 저장하며, 동일 요청의 재시도를 식별한다.

클라이언트는 마지막 기준 목록·로컬 수정·최신 서버 목록을 비교한다. 서로 겹치지 않는 변경은 병합하고 같은 필드의 상충이나 삭제/수정 충돌은 사용자에게 선택을 요청한다. 서버 확인 없이 저장 완료로 표시하지 않는다. 네트워크 실패 시 수정과 기준을 보존하고 재연결 후 최신 revision으로 검토한다.

초기화 취소는 과거 목록 전체를 대입하지 않고 초기화의 역방향 차이를 최신 목록에 병합한다. 이후 원격 추가·별도 편집을 보존하며 충돌이나 항목 수 초과 시 취소를 차단한다. 컨트롤러의 실제 미저장 변경 여부로 `beforeunload`를 등록하므로 단순한 오프라인 조회 실패에는 떠나기 경고를 띄우지 않는다.

공유 데이터는 항목의 이름·등급·포함 여부뿐이다. 기록, 당첨 제외 ID, 소리 설정, 대기 알과 후보 스냅샷은 각 브라우저의 개인 상태다. 서버 목록 변경은 이미 뽑은 알의 후보를 교체하지 않는다.

등급 확률은 상 60%, 중 35%, 하 4.9%, 극하 0.1%다. 각 등급 안에서 선택 가능한 항목은 같은 확률을 갖는다. 당첨 제외는 해당 등급의 후보 집합에만 적용한다. 어느 등급이든 후보가 없으면 전체 뽑기를 막으며, 확률을 다른 등급으로 재분배하지 않는다.

## 대기 알과 저장 상태

뽑기 시작부터 공개 완료까지 하나의 추첨 상태를 유지한다. 공개 대기 중인 알은 localStorage에 저장하고 새로고침 후 복원한다. 복원·애니메이션 재생·반복 클릭이 등급이나 확정된 결과를 바꾸거나 기록을 중복 추가하지 않도록 전이를 제한한다. 진행 중인 추첨에 영향을 주는 항목 변경과 새 뽑기는 잠근다.

저장 데이터는 신뢰하지 않고 형식과 범위를 검증한다. 공유 연결·저장이 완료되지 않으면 새 뽑기를 막는다. 이미 대기 중인 알은 연결 실패 중에도 개인 후보 스냅샷으로 열 수 있다. localStorage 실패는 별도로 표시하며 새로고침 후 개인 상태 복원은 보장하지 않는다.

## 기존 데이터 이관

새 기본 벌칙은 청소 20분·설거지 전담을 상, 친구에게 커피 사기를 중, 배달 대신 직접 요리를 하, 미뤄둔 일 30분을 극하에 배치한다. 기존 기본 벌칙도 이 배치를 적용한다.

기존 사용자 항목과 기록은 보존한다. 등급 정보가 없는 사용자 항목은 상으로 옮기며, 이전 개별 가중치를 새 등급 확률로 환산하지 않는다. 기존 기록을 새 당첨으로 처리하지 않는다. 이전 기기 전용 목록은 공유 서버의 초기값으로 자동 업로드하지 않고 별도 보존한다. 사용자가 도움말의 가져오기를 실행했을 때 공유 목록에 추가한다. 비어 있는 등급은 편집 화면에서 채우도록 안내하며 자동 확률 재분배로 숨기지 않는다.

## 신뢰 경계

공유 항목은 사이트 방문자가 읽고 수정할 수 있는 공개 데이터다. RPC는 항목 수·이름 길이·등급·ID·요청 크기 등 허용된 형식을 검증하고 임의 테이블 접근을 허용하지 않는다. 기록·대기 알·설정은 브라우저에만 보관한다. 사용자 문자열은 React 텍스트로 렌더링하며 localStorage를 인증 수단으로 사용하지 않는다. publishable key는 공개 클라이언트 식별용이며 관리 권한을 부여하는 비밀 값이 아니다.

## 검증과 배포

`quality_gates.yaml`의 lint, typecheck, unit, build 검증을 수행한다. 기존 브라우저 시나리오는 페이지별 모의 RPC 저장소로 격리하여 공개 목록을 변경하지 않는다. 별도 공유 테스트는 두 브라우저 컨텍스트에 같은 모의 DB를 연결해 CAS, 병합, 충돌 UI, 실패 복구와 개인 상태 분리를 검증한다. 배포 검증은 실제 공개 사이트에서 고유 테스트 항목만 추가·수정한 뒤 해당 항목만 제거하며, 기존 사용자 항목과 동시 변경을 보존한다. `.vercelignore`는 로컬 기록·검증 자료를 업로드에서 제외한다.
