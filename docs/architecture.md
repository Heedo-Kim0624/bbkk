# bbob 아키텍처

## 실행 구조

React 19와 TypeScript로 만든 Vite 단일 페이지 앱이다. Vercel은 `npm ci` 후 `npm run build`를 실행하고 `dist`를 배포한다. 별도 API, 데이터베이스, 환경 변수는 필요하지 않다.

이틀 연속 러닝을 쉬었을 때 사용자가 직접 벌칙을 뽑는다. 운동 추적이나 날짜 계산 상태는 추가하지 않는다.

- `src/main.tsx`: React 진입점, Astryx의 사전 빌드된 코어·중립 테마 CSS와 앱 CSS 로드.
- `src/App.tsx`: 항목 편집, 확률 표시, 뽑기 진행과 결과, 기록 및 저장 UI.
- `src/lib/`: 가중치 선택, 확률 계산, 저장 데이터 검증 등 UI와 분리된 순수 로직.
- `src/index.css`: 아이보리·민트 글래스모피즘, 반응형 배치와 모션 감소 지원.
- `public/`: 정적 아이콘. `index.html`: 한국어 메타데이터.

## 디자인 시스템

Astryx 코어와 neutral 테마를 사용한다. 코어와 테마의 배포 CSS를 가져오므로 앱을 위한 별도 StyleX 컴파일 파이프라인은 두지 않는다. 프로젝트의 유리 패널과 뽑기 장면은 앱 CSS로 표현한다.

## 데이터 흐름

텍스트/가중치 입력 → 검증된 항목 배열 → 유효한 가중치 합으로 확률 정규화 → Web Crypto 난수로 한 항목 선택 → 애니메이션 → 결과와 기록 표시 → localStorage 저장.

당첨 제외 모드에서는 제외된 항목을 다음 추첨의 확률 분모에서 뺀다. 저장 데이터는 신뢰하지 않고 형식과 범위를 검증한다. 로컬 저장 오류는 앱 사용을 막지 않도록 처리한다.

## 기본 항목 전환

새 사용자는 같은 가중치의 벌칙 5개로 시작한다. 기존 localStorage의 항목과 기록은 유지한다. 이전 점심 기본 샘플과 정확히 일치하고 기록·제외 항목이 없는 경우에만 새 벌칙 샘플로 전환한다. 이름이나 가중치를 수정했거나 사용 기록이 있는 저장 상태에는 이 전환을 적용하지 않는다.

## 신뢰 경계

항목과 기록은 브라우저에만 보관된다. 사용자 문자열은 React 텍스트로 렌더링한다. 저장 데이터와 URL을 통해 코드를 실행하지 않는다. localStorage는 동일 출처에서 접근 가능한 편의 저장소이며 인증 수단으로 사용하지 않는다.

## 검증과 배포

`quality_gates.yaml`에 정의한 lint, typecheck, unit, build 검증을 수행한다. 실제 브라우저에서는 반응형 화면과 주요 상호작용을 검토한다. `.vercelignore`는 로컬 harness·기록·검증 자료를 배포 업로드에서 제외한다. 실제 계정 연결과 게시 단계는 승인 후 진행한다.
