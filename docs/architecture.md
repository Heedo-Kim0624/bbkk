# bbob 아키텍처

## 실행 구조

React 19와 TypeScript로 만든 Vite 단일 페이지 앱이다. Vercel은 `npm ci` 후 `npm run build`를 실행하고 `dist`를 배포한다. 별도 API, 데이터베이스, 환경 변수는 필요하지 않다.

이틀 연속 러닝을 쉬었을 때 사용자가 직접 벌칙을 뽑는다. 운동 추적이나 날짜 계산 상태는 추가하지 않는다.

- `src/main.tsx`: React 진입점, Astryx의 사전 빌드된 코어·중립 테마 CSS와 앱 CSS 로드.
- `src/App.tsx`: 등급 탭과 항목 편집, 알 뽑기·공개, 기록 및 저장 UI.
- `src/lib/`: 고정 등급 확률과 균등 선택, 대기 알 상태, 저장 데이터 검증·이관 등 UI와 분리된 로직.
- `src/index.css`: 아이보리·민트 글래스모피즘, 반응형 배치와 모션 감소 지원.
- `public/`: 정적 아이콘. `index.html`: 한국어 메타데이터.

## 디자인 시스템

Astryx 코어와 neutral 테마를 사용한다. 코어와 테마의 배포 CSS를 가져오므로 앱을 위한 별도 StyleX 컴파일 파이프라인은 두지 않는다. 프로젝트의 유리 패널과 뽑기 장면은 앱 CSS로 표현한다.

## 데이터 흐름

등급 탭의 텍스트 입력 → 검증된 등급별 항목 → 모든 등급의 선택 가능 여부 확인 → Web Crypto 난수로 고정 확률의 등급 선택 → 해당 등급의 알 표시 → 사용자 공개 동작 → 등급 안에서 균등 선택한 벌칙과 기록 표시.

등급 확률은 상 60%, 중 35%, 하 4.9%, 극하 0.1%다. 각 등급 안에서 선택 가능한 항목은 같은 확률을 갖는다. 당첨 제외는 해당 등급의 후보 집합에만 적용한다. 어느 등급이든 후보가 없으면 전체 뽑기를 막으며, 확률을 다른 등급으로 재분배하지 않는다.

## 대기 알과 저장 상태

뽑기 시작부터 공개 완료까지 하나의 추첨 상태를 유지한다. 공개 대기 중인 알은 localStorage에 저장하고 새로고침 후 복원한다. 복원·애니메이션 재생·반복 클릭이 등급이나 확정된 결과를 바꾸거나 기록을 중복 추가하지 않도록 전이를 제한한다. 진행 중인 추첨에 영향을 주는 항목 변경과 새 뽑기는 잠근다.

저장 데이터는 신뢰하지 않고 형식과 범위를 검증한다. 저장 실패는 앱 사용을 막지 않으며 현재 탭에서 계속 사용할 수 있게 한다. 이 경우 새로고침 후 복원은 보장하지 않고 보관 제한을 안내한다.

## 기존 데이터 이관

새 기본 벌칙은 청소 20분·설거지 전담을 상, 친구에게 커피 사기를 중, 배달 대신 직접 요리를 하, 미뤄둔 일 30분을 극하에 배치한다. 기존 기본 벌칙도 이 배치를 적용한다.

기존 사용자 항목과 기록은 보존한다. 등급 정보가 없는 사용자 항목은 상으로 옮기며, 이전 개별 가중치를 새 등급 확률로 환산하지 않는다. 기존 기록을 새 당첨으로 처리하지 않는다. 이관 결과 비어 있는 등급은 편집 화면에서 채우도록 안내하며 자동 확률 재분배로 숨기지 않는다.

## 신뢰 경계

항목·기록·대기 알은 브라우저에만 보관된다. 사용자 문자열은 React 텍스트로 렌더링한다. 저장 데이터와 URL을 통해 코드를 실행하지 않는다. localStorage는 동일 출처에서 접근 가능한 편의 저장소이며 인증 수단으로 사용하지 않는다.

## 검증과 배포

`quality_gates.yaml`에 정의한 lint, typecheck, unit, build 검증을 수행한다. 단위 검증에서는 등급 확률의 경계, 등급 내 균등 선택, 빈 등급 차단, 데이터 이관과 상태 복원을 확인한다. 브라우저에서는 네 탭, 알 공개와 키보드 조작, 대기 중 새로고침, 중복 기록 방지와 반응형 화면을 검토한다. `.vercelignore`는 로컬 harness·기록·검증 자료를 업로드에서 제외한다. 승인된 배포 범위에서 기존 Vercel 사이트를 갱신하고 공개 페이지를 확인한다.
