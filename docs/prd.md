# bbob 제품 요구사항

## 목적

이틀 연속 러닝을 쉬었을 때 벌칙 하나를 뽑는 한국어 웹사이트. 사용자는 벌칙 텍스트와 확률을 자유롭게 조정한다. 기존 글래스모피즘 디자인과 뽑기 기능을 유지하고 화면 문구를 최소화한다. Vercel에 정적 배포한다.

## 화면과 사용 경험

- 아이보리 배경, 민트 포인트, 반투명 유리 패널을 사용하는 미니멀한 디자인.
- 데스크톱에서는 뽑기와 편집 화면을 함께 보여주고 모바일에서는 자연스럽게 세로로 배치.
- 뽑기 진행 애니메이션과 결과 표시, 명확한 버튼 반응, 키보드 접근 및 모션 감소 설정 지원.
- 항목 추가·수정·삭제, 가중치 조정, 정규화한 실제 확률 표시.
- 당첨 항목 제외 선택, 뽑기 기록, 브라우저 내 설정 보관.
- 페이지 제목은 `bbob — 러닝 약속`, 핵심 안내는 `이틀 연속 쉬면, 벌칙 하나.`로 짧게 표현한다.

## 기능 규칙

- 기본 벌칙은 청소 20분, 설거지 전담, 친구에게 커피 사기, 배달 대신 직접 요리, 미뤄둔 일 30분의 5개이며 각각 20%로 시작한다.
- 항목 이름은 사용자 입력 텍스트이며 HTML로 실행하지 않는다.
- 가중치에 비례하여 당첨 확률을 계산한다. 전체를 직접 100으로 맞출 필요가 없다.
- 가중치 0인 항목은 뽑히지 않는다. 뽑을 수 있는 항목이 없으면 실행을 막고 안내한다.
- 결과는 브라우저의 Web Crypto 난수로 선택한다. 애니메이션은 선택 확률에 영향을 주지 않는다.
- 애니메이션 진행 중 중복 실행과 설정 변경이 결과를 바꾸지 않아야 한다.
- 설정과 기록은 해당 브라우저의 localStorage에 저장한다. 손상되거나 저장이 제한된 환경에서도 앱이 동작해야 한다.
- 기존 사용자가 수정한 항목과 뽑기 기록은 보존한다. 이전 점심 기본 샘플과 정확히 일치하고 기록·제외 항목이 없는 상태만 새 기본 벌칙으로 전환한다.

## 범위

러닝 여부와 이틀 연속 휴식 여부는 사용자가 직접 판단한다. 운동 추적, 달력, 연속 일수 자동 계산, 로그인, 결제, 서버 데이터베이스, 기기 간 동기화는 포함하지 않는다.

## 구현 계획과 검증 경로

1. PRD와 구조 문서를 확정하고 가중치 선택·상태 복원의 단위 검증을 준비한다.
2. React/TypeScript UI, 입력 검증, 애니메이션, 로컬 저장 기능을 구현한다.
3. lint, TypeScript, 단위 테스트, 프로덕션 빌드를 실행한다.
4. 데스크톱과 모바일에서 입력·확률 변경·뽑기·기록·반응형 화면을 검토한다.
5. Vercel 설정과 배포 안내를 제공하고 게시 여부를 명확히 보고한다.

## 수용 기준

- 텍스트 항목과 가중치를 조정한 뒤 그 비율에 따른 결과를 얻을 수 있다.
- 유효하지 않은 입력과 모든 항목 제외 상태에서 런타임 오류가 발생하지 않는다.
- 모바일 화면에서 핵심 동작을 가로 스크롤 없이 사용할 수 있다.
- `quality_gates.yaml`의 필수 자동 검증을 통과하고 빌드 산출물 `dist`가 생성된다.
- 실제 수행한 검증만 완료로 기록한다. 비밀 값과 개인 계정 데이터는 읽거나 저장하지 않는다.
