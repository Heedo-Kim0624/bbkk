# bbob 제품 요구사항

## 목적

이틀 연속 러닝을 쉬었을 때 벌칙 하나를 뽑는 한국어 웹사이트. 사용자는 모두가 함께 쓰는 네 등급의 벌칙 목록을 편집하고, 펼쳐진 타로 카드 중 한 장을 골라 결과를 확인한다. 기존 미니멀 글래스모피즘 디자인과 최소 문구를 유지한다. Vercel 정적 앱과 Supabase 공유 저장소를 사용한다.

## 나머지 카드 공개 — 2026-09-23

- 카드 다섯 장의 내용은 펼치기 전에 각각 정하고 개인 브라우저에 보관한다. 한 장을 고르면 해당 카드가 당첨되고 나머지 네 장도 뒤집어 내용을 보여준다. 선택 후 가상의 내용을 만들어 붙이지 않는다.
- 각 카드마다 상60%·중35%·하4.9%·극하0.1%를 독립 적용하고 등급 안에서는 균등 선택한다. 확률 유지를 위해 같은 벌칙이 여러 카드에 나올 수 있다.
- 당첨 카드만 강조하고 기록·중복 제외에는 선택한 카드 한 장만 반영한다. 나머지 카드는 결과를 바꾸는 선택 버튼이 아니다.
- 공개한 다섯 장과 선택 위치도 개인 상태로 보관하여 새로고침 후 같은 결과를 확인할 수 있다. 공유 목록 변경으로 이미 펼친 카드 내용이 바뀌지 않는다.
- 이전 미개봉 데이터는 기존 확정 등급과 후보를 유지해 다섯 장으로 옮긴다. 기존 기록과 공유 데이터는 보존한다.
- 모바일에서는 선택한 카드 아래 네 장을 읽기 편하게 배치한다. 긴 텍스트·키보드·모션 감소·단일 기록·저장 복원·동시 공유 편집을 검증한 뒤 기존 공개 주소에 재배포한다.

## 타로 카드 전환 — 2026-09-23

- 유리공과 알 대신 다섯 장의 타로 카드 뒷면을 부채꼴로 펼친다. `카드 뽑기` → 섞기 → 원하는 한 장 선택 → 선택한 카드가 중앙에서 뒤집히며 벌칙을 공개한다.
- 아이보리·민트 유리 패널은 유지하고 카드 뒷면에 짙은 초록과 섬세한 금빛 선 장식을 쓴다. 결과 카드 앞면은 기존 네 등급의 흰색·파란색·금색·빛나는 금색을 반영한다.
- 각 카드 위치는 같은 등급 확률을 적용받는다. 펼치기 전에 카드별 내용을 확정하고 선택한 위치의 결과를 한 번만 기록한다.
- 기존 미개봉 알 저장 데이터도 같은 대기 추첨으로 받아 카드 선택 화면으로 복원한다. 공유 목록·기록·확률·중복 제외는 변경하지 않는다.
- 카드 선택은 마우스·터치·키보드를 지원한다. 모션 감소 설정과 모바일 320px, 긴 벌칙 이름에 대응한다. 새 뽑기/편집은 섞기·선택·뒤집기 도중 잠근다.
- 검증 경로: 기존 단위 검증, 카드 선택/뒤집기/새로고침/중복 방지 브라우저 검증, 공유 목록 회귀, 반응형 시각 확인, 빌드 후 기존 공개 주소에 재배포 및 실제 사이트 확인.

## 화면과 사용 경험

- 아이보리 배경, 민트 포인트, 반투명 유리 패널을 사용하는 미니멀한 디자인.
- 데스크톱에서는 뽑기와 편집 화면을 함께 보여주고 모바일에서는 자연스럽게 세로로 배치.
- 다섯 장을 부채꼴로 펼치고, 한 장을 고르면 중앙에서 뒤집혀 등급과 벌칙을 공개한다.
- 상·중·하·극하 탭에서 해당 등급의 항목을 추가·수정·삭제한다.
- 등급은 색 외에도 텍스트로 구분한다. 카드 공개는 키보드로도 실행할 수 있고 모션 감소 설정을 지원한다.
- 공유 목록 연결·저장·충돌 상태를 짧게 표시하고, 개인 당첨 제외·기록·카드·설정은 각 브라우저에 보관한다.
- 페이지 제목은 `bbob — 러닝 약속`, 핵심 안내는 `이틀 연속 쉬면, 벌칙 하나.`로 짧게 표현한다.

## 기능 규칙

- 등급과 확률·카드 앞면은 아래 표로 고정한다. 각 등급 안에서는 뽑을 수 있는 벌칙을 균등하게 선택한다.

| 등급 | 전체 추첨 확률 | 카드 앞면 | 기본 벌칙 |
| --- | --- | --- | --- |
| 상 | 60% | 흰색 | 청소 20분, 설거지 전담 |
| 중 | 35% | 파란색 | 친구에게 커피 사기 |
| 하 | 4.9% | 금색 | 배달 대신 직접 요리 |
| 극하 | 0.1% | 빛나는 금색 | 미뤄둔 일 30분 |

- 항목 이름은 사용자 입력 텍스트이며 HTML로 실행하지 않는다.
- 어느 등급이든 유효한 항목이 없으면 뽑기를 막고 해당 탭에 항목을 채우도록 짧게 안내한다. 남은 등급의 확률로 재분배하지 않는다.
- 당첨 항목 제외로 한 등급의 선택지가 소진되어도 뽑기를 막는다. 항목을 추가하거나 전체 항목을 다시 포함할 수 있게 안내한다.
- 결과는 브라우저의 Web Crypto 난수로 선택한다. 애니메이션은 등급 확률과 등급 내 균등 확률에 영향을 주지 않는다.
- 카드를 공개하면 벌칙과 등급을 표시하고 기록을 한 번만 추가한다. 애니메이션이나 공개 대기 중 중복 실행·설정 변경이 해당 결과를 바꾸지 않아야 한다.
- 항목의 이름·등급·포함 여부는 하나의 공유 목록으로 저장하며 다른 브라우저에서 추가·수정·삭제를 확인할 수 있어야 한다.
- 개인 설정·당첨 제외·기록·공개 대기 및 완료된 다섯 카드는 해당 브라우저에만 저장한다. 카드 내용은 뽑기 시작 시점의 목록으로 고정하며 다른 사용자의 목록 수정이 이미 뽑은 카드를 바꾸지 않는다.
- 새 뽑기는 공유 목록이 연결되고 저장 완료된 상태에서만 허용한다. 연결이 끊겨도 이미 뽑은 카드는 열 수 있다.
- 새로고침 후 같은 카드와 개인 기록을 복원한다. localStorage가 제한된 경우 보관 제한을 안내한다.
- 기존 사용자 항목과 기록은 보존한다. 등급이 없는 기존 사용자 항목은 상으로 옮기며, 이전 기본 벌칙은 표의 등급으로 배치한다. 기존 기록을 새로운 당첨으로 다시 기록하지 않는다.

## 범위

러닝 여부와 이틀 연속 휴식 여부는 사용자가 직접 판단한다. 하나의 공개 공유 목록과 기기 간 항목 동기화를 포함한다. 로그인, 개인별 공유 방, 운동 추적, 달력, 연속 일수 자동 계산, 결제, 개인 기록 동기화는 포함하지 않는다.

## 공유 편집 규칙

- 입력 변경은 약 550ms 후 자동 저장한다. 서버의 목록과 revision을 읽고, 예상 revision이 일치할 때만 변경을 적용한다.
- 서로 다른 항목·필드의 동시 편집은 기준 목록을 이용한 3방향 병합으로 보존한다. 같은 필드의 상충하는 수정이나 삭제와 편집의 충돌을 조용히 덮어쓰지 않는다.
- 충돌 시 `수정 충돌` 상태를 표시하고 `최신 목록` 또는 `내 수정 적용`을 사용자가 선택한다. 네트워크 실패 시 수정 내용을 보존하며 `다시 연결`로 복구한다.
- 초기화는 공유 목록 전체에 영향을 주므로 확인 화면에 `모두의 목록이 바뀝니다.`를 표시한다.
- 초기화 되돌리기는 해당 초기화가 바꾼 차이만 복원하며 이후 다른 사용자가 추가·수정한 내용은 보존한다. 복원이 최신 편집과 충돌하면 실행하지 않고 안내한다.
- 서버에 아직 저장되지 않은 수정이나 응답이 불확실한 저장 요청이 있을 때만 페이지를 떠나기 전 브라우저 경고를 표시한다. 수정 없는 연결 실패만으로 경고하지 않는다.
- 이전 브라우저 전용 목록을 서버 목록으로 자동 덮어쓰지 않는다. 해당 기기의 기존 목록을 보존하고 `이 기기의 목록 가져오기`를 선택했을 때만 공유 목록에 추가한다.
- 공유 목록에 적는 내용은 이 사이트를 사용하는 다른 사람도 볼 수 있고 수정할 수 있다. 개인 기록·카드·설정은 공유하지 않는다.

## 구현 계획과 검증 경로

1. 기존 확률·공유/개인 데이터 경계를 유지하는 카드 선택 흐름을 확정한다.
2. 타로 카드 표현 컴포넌트와 선택·뒤집기 잠금을 붙이고 유리공·알 표현을 제거한다.
3. lint, TypeScript, 단위 테스트, 프로덕션 빌드를 실행한다.
4. 모의 DB에서 카드 선택·기존 대기 데이터 복원·반복 실행 방지와 공유 동기화 회귀를 검사하고, 모바일·키보드·모션 감소 표현을 확인한다.
5. 검증한 변경을 기존 Vercel 사이트에 재배포하고 공개 페이지 결과를 별도로 확인한다.

## 수용 기준

- 상 60%, 중 35%, 하 4.9%, 극하 0.1%와 각 등급 내 균등 선택이 결정적 경계 테스트를 통과한다.
- 네 탭에서 텍스트 항목을 편집할 수 있고 등급에 맞는 카드와 벌칙이 표시된다.
- 빈 등급·소진 등급에서 고정 확률을 바꾸지 않으며 복구 동작을 제공한다.
- 새로고침으로 대기 카드를 바꾸거나 기록을 중복 추가하지 않는다. 기존 사용자 항목과 기록을 유지한다.
- 서로 다른 브라우저에서 공유 항목 변경을 확인하며, 동시 편집·충돌·네트워크 실패가 기존 변경을 조용히 지우지 않는다.
- 공유 항목 수정과 개인 카드·기록이 분리되고, 목록 초기화 전에 공유 영향이 명시된다.
- 모바일 화면에서 핵심 동작을 가로 스크롤 없이 사용할 수 있다.
- `quality_gates.yaml`의 필수 자동 검증을 통과하고 빌드 산출물 `dist`가 생성된다.
- 실제 수행한 검증만 완료로 기록한다. 비밀 값과 개인 계정 데이터는 읽거나 저장하지 않는다.
